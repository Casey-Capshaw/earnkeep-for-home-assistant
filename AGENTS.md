# EarnKeep — instructions for coding agents

These are the project instructions for any AI coding agent (Codex, Cursor,
Copilot, Gemini, Claude Code and others). Claude Code reads them through
`.claude/CLAUDE.md`. People contributing by hand will find the same ground
rules in [CONTRIBUTING.md](CONTRIBUTING.md).

EarnKeep is a Home Assistant custom integration for kid accountability and
banking: daily habits, weekly compensated accountabilities, bank balances,
monthly interest, and a living, procedurally drawn world with each kid's
animated Sprite. This repo is the whole thing: the Python backend and the
React/Vite frontend.

If an `AGENTS.local.md` or `CLAUDE.local.md` exists at the repo root
(gitignored), read it too. It holds one household's deploy targets and notes,
which never belong in this file.

## Terminology

- **Habit** = `type: "daily"`: a routine task, no pay.
- **Accountability** = `type: "compensated"`: tied to weekly compensation,
  all-or-nothing.
- **Sprite**: a family member's animated character in the world, described by
  a Sprite character file (see `docs/sprites/`).
- The project says *accountabilities* and *compensation*, never *chores* or
  *allowance*, in the app and in docs.

## Repo layout

- `custom_components/earn_keep/`: the deployable Home Assistant component
  (Python and the bundled JS).
- `frontend/`: React/Vite TypeScript source. It builds to
  `custom_components/earn_keep/frontend/earn-keep-panel.js`.
- `frontend/src/world/`: the living world (date-seeded layered scene, weather,
  holidays). `frontend/src/world/sprites/`: the Sprites: the character
  format (`traits.ts`), drawing (`Sprite.tsx`, `hair.tsx`, `aids.tsx`) and the
  games (`episodes.ts`).
- `frontend/dev/`: a mock Home Assistant harness. `npx vite` in `frontend/`,
  then open `/dev/` (the app) or `/dev/sprites/` (the Sprite gallery).
- `custom_components/earn_keep/combo.py`: the combo rules.
- `scripts/build.sh`: builds the frontend.
- `scripts/deploy.sh`: builds, copies to a Home Assistant host over SSH
  (hash-verified, and the previous deploy is kept), reloads the config entry
  and checks the served bundle. Hosts come from a gitignored `.env` (see
  `.env.example`). **Python changes need a Home Assistant core restart**,
  because an entry reload doesn't re-import modules.
- `scripts/release.sh`: checks the build and the built bundle, then tags and
  creates a GitHub release from the `manifest.json` version.
- `scripts/sfx/synth.py`: synthesizes every sound effect
  (`--install <set>` writes `custom_components/earn_keep/sounds/`).
- `brand/`: the logo and brand kit (generated by `brand/build.py`).
- `docs/architecture.md`: how the pieces fit together. Keep it current when a
  change alters the design. `docs/tablet.md`: setting up a wall tablet.

## Checks

Run what your change touches before you call it done:

| Command | What it checks |
| --- | --- |
| `python3 -m unittest discover tests` | Backend unit tests |
| `npm --prefix frontend test` | Frontend unit tests (traits, intake, wardrobe, the games with one to four kids) |
| `cd frontend && npx tsc --noEmit` | Types |
| `node scripts/sprite-parity.mjs` | Sprite drawings against snapshots, and that every accepted trait value is drawn (`--update` after an intended change) |
| `node scripts/verify-visual.mjs` | Roles, Bank and special days at the tablet size (1280×800) |
| `node scripts/verify-admin.mjs` | The PIN gate and every Admin tab |
| `node scripts/verify-bundle.mjs` | The built `earn-keep-panel.js` itself renders |

The visual scripts save screenshots to `frontend/dev/screenshots/`; look at
them. CI runs the backend tests, hassfest and the HACS check.

## Working agreements

- **Commit the rebuilt `earn-keep-panel.js`** with frontend changes
  (`scripts/build.sh`). The bundle is tracked, and HACS installs ship it as is.
  A fresh build must reproduce the committed file exactly.
- **Deploy only from an up-to-date `main`** (`git fetch` first). A stale local
  `main` can silently revert fixes that are already live.
- **Design for the tablet:** 1280 × 800 CSS pixels at 1.5×. The panel renders
  inside Home Assistant's shadow DOM, so `@font-face` and Tailwind `@property`
  rules go in the document head, and dialogs portal into the panel.
- **No personal data in the repo:** no real names, birthdays, photos or
  likenesses of children, and no home-network addresses. Mock data,
  screenshots and tests use the fictional family (Owen and Hazel, with the
  `fern` and `rowan` Sprites). A household's own characters are data in Home
  Assistant's storage, never code.
- Don't commit secrets, tokens, `.env`, `AGENTS.local.md`, `CLAUDE.local.md`
  or `frontend/dist/`.
- Keep the README's screenshots current with `node scripts/readme-screenshots.mjs`
  when the look of the app changes.
